# 四個實作版本 × 坍縮開關｜十萬局比對
2026/09/18　種子 0–99999，`--no-cap`（移除 200 輪外部上限），終局不變量違規皆為 0

三處差異都來自規則文件沒有寫明、實作者自行選擇的地方：抽牌順序、丟對子時機、手牌上限。四個版本都通過全部驗證腳本。

| vC7b | ＋丟對子時機 | 51.2／49／81／98／146 | 53.9／52／88／108／177 | 0 ／ 0 | 坍縮讓局變短 |

vC6.1 超過 200 輪的四局：種子 14648、15156、26799、68619，最長 240 輪（移除上限後自然終止）。

## 三件事

1. **每一次修正都大幅改變數字。** 只改抽牌順序時平均從 53.6 跳到 79.6，補上丟對子時機後又降回 51.2。任何一個中間版本單獨看，都會得到不同的結論。
2. **結論的方向會翻轉。** vC6.1 顯示坍縮讓局變長，據此推翻了設計文件的「加速收斂」；三個修正版都顯示坍縮讓局變短，設計意圖成立。
3. **「未收斂」只存在於錯誤的實作。** vC6.1 有 4 局、vC7a 有 84 局超過 200 輪；修正丟對子時機之後完全消失。原先「規則覆蓋缺口、局面自鎖」的推論，是實作的產物。

終止性仍未被證明，只是在十萬局裡沒有反例。

## 重現方式

```
python3 montecarlo_verify.py -n 100000 --no-cap -e <引擎>
python3 montecarlo_verify.py -n 100000 --no-cap --no-collapse -e <引擎>
```

vC6.1 原檔沒有 COLLAPSE_TURN 與 TURN_CAP 參數，無法關閉坍縮或移除上限。本次以 `反向抽鬼牌vC6.1_參數版.py` 執行：只把第 20 輪的坍縮觸發與 200 輪上限改成讀取這兩個模組層參數，其餘實作完全未動；同參數下（-n 2000）與原檔數字完全一致。
